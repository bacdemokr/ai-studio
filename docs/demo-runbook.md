# A useful agent you can see — presenter runbook

## Before attendees arrive

Start the chosen model, OpenClaw and app. Check `./bac llm check` and `./bac runtime check`. Keep one model active across all agents. Connect optional Telegram/search credentials yourself; never bake them into an image. If using OpenShell, run a real mission and inspect the actual sandbox before describing it as enforced.

Open Agent Studio in a fresh browser profile. Confirm WebGL movement, no horizontal overflow, and a green runtime indicator. Inference latency depends on the selected model and hardware; do a timed rehearsal on the actual Spark. Keep the separate, visibly labeled Workflow rehearsal available for a service outage.

## 0–2 minutes: a teammate with a personality

Ask the attendee to name their agent and choose Guide, Maker or Analyst. Let them change the skill loadout. The same identity appears in the world and survives refreshes. Explain that a persona changes how the agent approaches work; a skill supplies reusable instructions, and tool access is checked separately.

## 2–5 minutes: a visible, useful result

Click the 3D Maker workshop. Request a tiny reaction-time game, wait for the real agent response, and open the saved HTML. Play it. The result is a file, not an animation of an imagined task. If generation fails, show the actual error and a local tool or a labeled rehearsal; do not claim a fallback is a live success.

Alternative: click Knowledge library, add the sample brief or your own .txt/.md/.csv, and ask for an answer with filename evidence. Or click Weather lookout for a current observation and source.

## 5–7 minutes: memory and continuity

Ask the agent to remember a preference. Open Memory to inspect the actual file, refresh, and ask what it remembers. If Telegram was configured, pair the participant’s private chat and ask the same question there. Web and phone use the same OpenClaw session, not two bots pretending to remember.

## 7–13 minutes: why several agents?

Launch a BaC in Zurich, Europe / EMEA, in English. Let the attendee change attendance, duration and group/session sizes. Their agent becomes the event lead. Nova designs the participant experience; Atlas explains deterministic device/staff counts; Momo uses those outputs for invitation copy; Pico reviews the combined plan.

Open A to see personalities and movement. Switch to C to inspect dependencies and completed deliverables. Deliberately enter too few devices. The server stops before marketing; the attendee can plan additional equipment (still unconfirmed) or cancel and revise the brief. The review calls out missing dates/venue/registration links.

Explain the value in concrete terms: each role has a clear responsibility, its own context, and an output another role can inspect. The reviewer can catch inconsistencies. A single short task does not need a crew; a coordinated plan benefits from explicit dependencies. This implementation runs sequentially on one LLM, so it does not promise faster execution from concurrency.

## 13–15 minutes: make it their own

Edit persona/skills after the mission finishes. Schedule a one-minute follow-up; the queue survives refresh. Download the final plan, mini app or report. No invitation email is sent from the demo. Optional browser voice playback reads the answer; this is browser speech, not a separate voice model.

## Presentation boundaries

Keep the dark NVIDIA-inspired shell and familiar panel layout. Use Expand world only when showing the spatial experience. Character wandering is ambient when idle; movement toward a station represents an observed task state. The evidence panel contains app events and actual files, not a fine-grained tool trace or hidden reasoning.

OpenClaw owns agent execution, identity, skills, tool use and conversation state. The BaC app owns onboarding, the shared brief, role orchestration, scheduling and UI. OpenShell is the optional execution sandbox; an application approval is not proof of an OpenShell policy boundary.
